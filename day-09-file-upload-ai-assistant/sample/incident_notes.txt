Incident: Elevated API errors in production

Start time: 09:15 UTC
End time: 09:42 UTC

Impact:
- Checkout API returned intermittent 500 errors.
- Approximately 8 percent of checkout requests failed.
- Read-only catalog traffic was not affected.

Timeline:
- 09:15 UTC: Alert fired for elevated 5xx responses.
- 09:18 UTC: Platform team noticed a new deployment completed five minutes earlier.
- 09:24 UTC: Error logs showed database connection pool exhaustion.
- 09:31 UTC: Deployment was rolled back.
- 09:42 UTC: Error rate returned to normal.

Likely cause:
The new deployment reduced the database connection timeout and increased retry volume during slow queries. The retry behavior exhausted the connection pool.

Follow-up actions:
- Add retry backoff to the checkout database client.
- Load test connection pool behavior before the next release.
- Add dashboard panels for retry volume and pool saturation.
